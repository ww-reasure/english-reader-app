# 统一移动端学习工作台设计

**状态：** 已确认方向，等待用户审阅实现说明  
**日期：** 2026-07-21

## 目标

将英语阅读助手从“首页是一套对话外观、其他页面仍是一套底部导航”的混合体验，收敛为一套面向手机的学习工作台。

完成后，用户可以：

- 在任意页面用同一顶部栏和侧抽屉切换模块；
- 在首页与 AI 进行真正的学习对话；
- 明确地选择“聊天”或“生成阅读”，不再把所有输入都误认为文章需求；
- 在 320–430 CSS 像素宽的 Android 手机上不出现横向溢出、内容裁切或底栏遮挡；
- 不能通过双指缩放破坏界面比例。

保留既有文章、词库、复习、导入、测评、深浅主题、词典和句子分析能力。

## 已确认的产品方向

采用 **全局顶部栏 + 侧抽屉** 作为唯一主导航。

- 删除全局五栏底部导航，不在任何页面保留第二套主导航。
- 首页默认是“学习对话”；文章生成是可见且独立的模式，而不是默认发送行为。
- 顶部栏承担菜单、当前页面标题，以及该页面必要的次级动作。
- 侧抽屉保留原有五个一级入口：学习对话、阅读记录、词汇学习、书架、学习档案；设置和测评作为档案内的次级入口。

## 信息架构与导航

### 全局工作台壳

新增一个由路由驱动的共享页面壳，而不是只在首页添加 `chat-shell-active`。

共享壳包括：

1. 固定在安全区内的顶栏：左侧菜单、居中页面名称、右侧上下文动作。
2. 全局侧抽屉：打开时覆盖内容、锁定背景滚动；关闭后把焦点还给菜单按钮。
3. 仅内容区滚动：标准页面自然滚动；阅读页继续由正文阅读体验主导；首页由消息区独立滚动。

一级入口和页面标题：

| 路由 | 抽屉名称 | 顶栏标题 |
| --- | --- | --- |
| `#/chat` | 学习对话 | 英语学习助手 |
| `#/history` | 阅读记录 | 阅读记录 |
| `#/vocab` / `#/learn-words` / `#/flashcard` | 词汇学习 | 词汇学习 / 单词复习 |
| `#/reading-list` / `#/reading/:id` | 书架 | 我的书架 / 阅读 |
| `#/profile` | 学习档案 | 学习档案 |
| `#/settings` / `#/assessment` / `#/report` | 档案内入口 | 设置 / 水平测评 / 学习报告 |

当前路由在抽屉中高亮；从侧抽屉离开首页时不再出现旧底栏。

### 例外页面

阅读正文、测评答题和卡片复习不使用首页输入器，但仍使用同一顶栏与侧抽屉入口。它们只保留完成任务所需的正文、进度和底部局部操作，不能再出现全局五栏底部导航。

## 首页：真实学习对话

### 初始状态

首页不再优先堆叠旧文章卡片。消息区初始显示：

- 一条简短欢迎语，说明可提问英语、翻译、语法、学习计划；
- 若存在待复习词，展示一张可前往复习的紧凑提醒卡；
- 若已有生成或聊天记录，按时间展示最近记录。

文章仍可作为聊天中的一张“阅读结果卡”出现，但卡片只显示标题、难度、词数、预览与“开始阅读”，不在消息区重复展开长文。

### 两种明确模式

输入器上方或左侧提供可见的模式入口，默认是 **对话**。

| 模式 | 发送后行为 | 输入提示 |
| --- | --- | --- |
| 对话（默认） | 将内容发送给学习助手，返回普通文本回复 | 例如：帮我解释 `take for granted` |
| 生成阅读 | 使用既有难度、话题、词库融入配置生成一篇文章 | 想读什么主题、词汇或场景？ |

“随机一篇”“复习阅读”始终直接进入相应生成流程；“科技、心理学、旅行”等快捷项切换到生成阅读并预填主题。导入文章、导入单词和学习词库保留为真实功能入口。

### 对话行为

普通消息调用同一 OpenAI 兼容的 `/chat/completions` API；新增通用 `API.chat` 封装。

- 系统提示将 AI 限定为中文为主的英语学习助手：解释词义、语法、翻译、改写、阅读策略和复习建议。
- 请求仅携带最近的有效对话上下文，避免把文章原文、系统提示和旧错误无限累积。
- 用户消息、助手回答、系统提醒、错误消息、文章卡片分别存为有类型的本地历史记录。
- 发送中在消息区出现一个可读的“正在思考”状态，同时禁用当前发送按钮；失败则保留用户原消息并显示可重试的错误气泡。
- 清空对话会先二次确认，并只清除对话历史；已保存文章、词库和学习记录不受影响。

## 视觉与移动端规则

延续现有米白纸张、深墨文字、珊瑚红强调色、衬线英文标题的阅读气质，但去掉旧首页中过多的大块卡片和重复边框。

- 顶栏高度、间距、按钮尺寸、圆角和阴影由全局 token 统一；不用表情符号充当界面图标，改用现有可用的线性图标资源或小型图标库。
- 普通页面内容宽度为 `min(100%, 720px)`，在手机上使用 16px 左右的安全边距；所有标题、文章预览、筛选控件与按钮允许换行，不能设置导致横向溢出的最小宽度。
- 首页固定采用 `100dvh` 三段网格：顶栏 / 可滚动消息区 / 快捷栏与输入器。输入器只固定在首页；消息增加时只滚动消息区。
- 快捷栏使用原生横向滚动、滚动吸附、触摸惯性，并保留右侧露出提示，不使用分页指示或占用内容高度的底栏。
- 所有页面使用 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)`，没有固定元素遮挡系统手势区。
- 根视口固定为设备宽度，关闭用户缩放；同时不依赖缩放来修复布局，布局本身必须适配 320px 宽度。
- 主题色变量继续同时支持亮色和深色模式；抽屉、输入器、消息气泡和错误状态都需要各自的深色样式。

## 数据与兼容策略

- 保留现有 `chatHistory` 键；加载时兼容已有 `user`、`system`、`error` 和 `article` 条目。
- 新增的聊天记录使用明确角色与文本字段；渲染器对未知旧类型采用安全的系统提示样式，不能使首页白屏。
- `PendingArticles` 仍用于用户离开首页后完成的文章生成；通知位置从旧底栏徽标迁移到抽屉中的“学习对话”入口。
- 不改变 IndexedDB 的文章和词库结构，不改变生成文章、复习文章、词典和句子分析的接口契约。

## 故障与边界

- 未配置 API 时，用户首次发送或生成才打开 API 设置，不用遮挡首页内容的强制弹窗阻断浏览。
- 网络、超时、解析错误都以简短可操作的消息显示；文章生成失败不创建空文章。
- 路由离开时取消或忽略晚到的聊天/生成结果，防止旧页面的结果插入新页面。
- 抽屉、设置面板、导入弹窗和词典卡片叠放顺序统一；打开任一全局弹层时不允许背景页面滚动。

## 验收与测试

### 手机布局

- 在 320×568、360×800、390×844、412×915、430×932 视口检查首页、记录、词汇、书架、档案、阅读与测评。
- 页面无横向滚动、无被截断标题、无被安全区或固定控件遮挡的主要按钮。
- 双指缩放不改变页面缩放比例；文字和交互目标仍保持可读和可点。

### 导航

- 任意一级页面都只存在统一顶栏与抽屉，不存在五栏底部导航。
- 抽屉打开、关闭、当前项高亮、切换路由、返回首页与深色主题均正确。

### 学习对话与文章生成

- 默认发送普通问题，显示用户与助手气泡，并带上有限的最近上下文。
- 切换生成阅读后，难度、话题、自定义话题、Enter 发送和生成按钮仍有效。
- 快捷的随机生成、复习阅读、导入文章、导入单词、学习词库都继续可用。
- 聊天、文章、提醒、网络失败和离开页面后的异步结果分别验证。

### 回归

- 运行现有 Node 测试，并为新路由壳、聊天上下文裁剪、旧记录兼容、模式切换和移动视口锁定补充测试。
- 运行生产构建、Capacitor 同步和 Android Debug 构建。
- 对比同一 412×915 视口的改版截图与本设计，检查顶栏、抽屉、消息区、输入器及非首页页面的一致性。

## 不在本次范围内

- 语音输入、拍照识别、实时流式输出、多会话列表、云端聊天同步。
- 重写既有文章、词库和复习的业务数据模型。
- 改变单词翻译卡片已确定的显式关闭和滚动关闭规则。
