# 统一词库与词汇学习页设计

- 日期：2026-08-24
- 状态：已与用户确认
- 目标分支：`feat/english-practice-machine`
- 视觉方向：已选择 Product Design 第二稿“学习优先的统一词库”

## 1. 背景

当前 App 把词汇拆成两套数据和两个页面：

- 阅读中收藏的词写入 `vocabulary`，并尝试同步到 `learnWords`；
- 手动或 PDF 导入的词只写入 `learnWords`；
- `#/vocab` 的“词汇学习”页面只读取 `vocabulary`；
- `#/learn-words` 的“学习词库”页面读取 `learnWords`。

因此直接导入的词虽然能在“学习词库”看到，却完全不会出现在主导航的“词汇学习”页面。专项复习的今日新增、最近七天和手动选词也先从 `vocabulary` 出发，导入词无法完整参与。两套页面还分别承担删除、详情、筛选和复习入口，用户无法判断哪个才是真正的词库。

## 2. 目标

本次改造建立一个统一的“我的词汇”体验：

1. 阅读收藏和外部导入的词都在 `#/vocab` 可见。
2. `learnWords` 成为唯一主词库和正式 SRS 事实源。
3. `vocabulary` 只保存阅读收藏的文章、语境等附加信息。
4. 每个标准词形只对应一条主词记录和一套正式复习排期。
5. 来源可以同时包含“阅读收藏”和“外部导入”。
6. 今日新增、最近七天、手动选词覆盖全部来源并按词去重。
7. 原“学习词库”页面并入统一页面，旧链接安全重定向。
8. 移出词库采用归档，不擦除复习历史、日报事实或旧排期。

## 3. 非目标

本期不做：

- 不新增第三张词汇主表；
- 不重写 SRS V2、Recovery、正式评分或专项练习评分规则；
- 不批量生成缺失释义；
- 不猜测旧数据中无法证明的“收藏且导入”双重来源；
- 不增加云同步、标签、文件夹或多词本；
- 不修改真题、阅读文章、私有题包或日报保留规则；
- 不合并或推送 `main`。

## 4. 核心数据模型

### 4.1 主记录

继续使用 `learnWords` 作为唯一主词库。每条记录增加字段，但不新增对象存储：

```js
{
  librarySourceVersion: 1,
  librarySources: {
    reading: {
      active: true,
      firstAddedAt: 1787500000000,
      lastAddedAt: 1787500000000
    },
    import: {
      active: false,
      firstAddedAt: null,
      lastAddedAt: null
    }
  },
  libraryAddedAt: 1787500000000,
  archivedAt: null
}
```

字段语义：

- `librarySources.reading`：是否仍有阅读收藏来源，以及首次/最近收藏时间；
- `librarySources.import`：是否仍有外部导入来源，以及首次/最近导入时间；
- `libraryAddedAt`：本词首次进入统一词库的时间，用于“最近加入”和专项复习；
- `archivedAt`：非空时从普通词库、正式复习、文章复习和专项复习候选中隐藏；
- 来源历史与 SRS 字段相互独立，来源变化不能直接推进或重置排期。

`createdAt` 继续保留，兼容旧逻辑；新代码优先使用 `libraryAddedAt`，缺失时回退到 `createdAt`。

### 4.2 收藏附加记录

`vocabulary` 继续保存：

- 原始展示词形；
- 来源文章 ID；
- 原文语境；
- 收藏时保存的释义、音标和词性；
- 收藏时间。

它不再决定一个词是否属于正式学习词库。统一页面以 `learnWords.id` 作为选择、详情、归档和专项复习 ID。

## 5. 历史数据迁移

迁移采用字段级、幂等、可恢复的懒迁移，不升级 IndexedDB 版本，不把题包或首屏启动绑在迁移上。

首次读取统一词库时，在一个本地事务中按当前 `getStemForm` 规则匹配：

1. `vocabulary` 中存在的所有标准词形标记为 `reading.active = true`、`import.active = false`；
2. 剩余 `learnWords` 标记为 `reading.active = false`、`import.active = true`；
3. `vocabulary` 中存在但 `learnWords` 缺失的词补建为新学习词，保留收藏释义和最早收藏时间；
4. 旧数据不标记为“两者都有”；只有升级后真实发生过第二种来源行为才形成双来源；
5. 已带 `librarySourceVersion: 1` 的记录不重新推断，防止取消收藏后被误判为导入词；
6. 单条迁移失败时不删除原记录；当前页面可以使用内存推导结果，下一次进入继续补齐。

迁移不修改 `state`、`interval`、`easeFactor`、`nextReview`、`reviewCount`、`reviewRevision`、Recovery 字段或 `reviewEvents`。

## 6. 来源写入规则

### 6.1 阅读收藏

收藏成功时以标准词形原子完成：

1. 保存或复用 `vocabulary` 收藏记录；
2. 新建或读取对应 `learnWords`；
3. 激活 `librarySources.reading`；
4. 若主记录已归档则恢复；
5. 只有主记录此前不存在时才计为新增学习词；
6. 已存在的导入词增加收藏来源，但不产生第二条排期，不自动评分。

### 6.2 外部导入

导入成功时继续使用现有“每日每词一次”和外部复习信用规则，同时：

1. 新词写入 `librarySources.import`；
2. 已有收藏词激活导入来源，形成“两者都有”；
3. 归档词恢复原主记录，再按现有外部导入信号判断是否调整排期；
4. 同一天重复导入不重复计新增或外部复习，但必须保证已经恢复来源；
5. 导入来源变更、外部复习事件和每日去重保持事务一致。

## 7. 取消收藏、归档和恢复

### 7.1 取消收藏

- 仅收藏来源：删除对应收藏记录，停用阅读来源，并归档主词记录；
- 收藏且导入：删除收藏记录并停用阅读来源，主词仍以导入来源保留，SRS 不变；
- 取消收藏不删除 `reviewEvents`、日报、学习活动或旧排期。

### 7.2 移出词库

“管理”中的移出操作设置 `archivedAt`，不做硬删除。归档词：

- 不出现在统一列表；
- 不进入正式复习、文章复习、专项复习或待复习计数；
- 保留来源历史、SRS、Recovery 和复习事件；
- 不回写为“已掌握”。

### 7.3 再次加入

归档词以后再次收藏或导入时：

- 复用原 `learnWords.id`；
- 清除 `archivedAt`；
- 激活对应来源；
- 保留原学习基础；
- 外部导入继续走现有有界信用，不伪装为“认识”。

## 8. 统一词汇页面

### 8.1 页面结构

采用已选中的第二套视觉方向，在现有纸张质感、墨绿色和编辑式排版上实现：

1. 标题“我的词汇”和全部有效词数量；
2. 右侧主要动作“导入”；
3. 搜索框，可搜索单词、音标和中文释义；
4. 一级来源切换：“全部 / 收藏 / 导入”；
5. 一行学习状态：“今日新增 n / 待复习 n / 开始复习”；
6. “筛选”面板保留原学习状态：新词、学习中、待复习、长期巩固；
7. 排序：最近加入（默认）、A–Z、待复习优先；
8. 普通扁平列表，每行显示单词、音标、中文释义、来源和学习状态；
9. “管理”与“选词复习”互斥，菜单按钮始终由 App 壳层保留。

不使用多层卡片、横向滚动或两个并列词库。

### 8.2 来源筛选

- “全部”：每个主词只出现一次；
- “收藏”：包含阅读来源的词，包括双来源词；
- “导入”：包含导入来源的词，包括双来源词；
- 双来源词在列表中显示“收藏·导入”；
- 归档词不出现在任何普通筛选中。

### 8.3 排序

- 默认按 `libraryAddedAt` 倒序；
- 同一批次时间相同则按主记录 ID 倒序，保证稳定；
- A–Z 使用标准词形和稳定 ID；
- 待复习优先复用现有 due/recovery 优先级，未到期词随后按最近加入排列；
- 搜索和筛选只改变展示，不改排期或完成状态。

### 8.4 空状态与错误

- 主词库为空：显示导入和去阅读两个入口；
- 当前筛选为空：只显示“没有符合条件的单词”，不冒充整个词库为空；
- 迁移或列表读取失败：显示可重试提示，保留 App 壳层；
- 导入结束后当前页面原地刷新，不要求用户返回聊天页；
- 大词库先使用一次内存映射和稳定排序，不对每个列表项单独查询数据库。

## 9. 专项复习

`resolvePracticeScope` 改为直接使用未归档的 `learnWords`：

- `today_added`：`libraryAddedAt` 位于本地今日零点之后；
- `recent_added`：`libraryAddedAt` 位于最近七个本地自然日窗口；
- `manual`：直接接收统一页面选中的 `learnWords.id`；
- 同一词无论有一个还是两个来源都只出现一次；
- 归档词自动跳过；
- 今日/最近完成记录继续按现有 word ID 集合增量解锁；
- 专项评分继续只写 practice 事件，绝不改变正式 SRS。

## 10. 路由和入口收口

- `#/vocab` 是唯一可见词汇管理页面；
- `#/learn-words` 作为兼容别名，进入后替换为 `#/vocab`；
- 首页快捷操作、闪卡结果、语境复习结果、空队列和学习档案中的旧链接全部改到 `#/vocab`；
- 移除 `LearnWordsView` 的路由和独立页面实现；
- 页面文案统一使用“我的词汇”或“词汇学习”，不再让用户选择“生词本”和“学习词库”。

## 11. 下游兼容

- `DB.getAllLearnWords()` 默认只返回未归档词，现有 ReviewQueue、文章生成、词汇标记和 Agent 查询自然排除归档词；
- 增加显式 `includeArchived: true` 仅供历史统计、恢复和数据维护；
- 日报与长期统计不能因为归档而删除过去事实；需要历史总量时显式包含归档记录；
- 正式评分仍按 `learnWords.id` 和 `reviewRevision` 工作；
- 词典补全、例句、词根、近义词和真题语料详情继续复用现有 `WordStudyDetail`；
- `clearLearnWords()` 保留为内部彻底重置能力，但统一页面不再调用它。

## 12. 可访问性与响应式

- 手机宽度下来源切换、搜索和操作不产生横向滚动；
- 平板继续使用现有 rail 页面壳层；
- 搜索、筛选、排序、管理和复习按钮均可键盘操作并有可读标签；
- 选中来源使用文字和状态属性，不只依赖颜色；
- 管理/选择模式变化使用可见标题和按钮状态；
- 所有危险操作有具体影响说明和确认，不使用模糊“删除”。

## 13. 测试与验收

### 数据与迁移

1. 收藏表中的历史词标为收藏。
2. 剩余学习词标为导入。
3. 收藏存在但主词缺失时补建新词。
4. 历史迁移不制造双来源。
5. 迁移重复执行结果不变。
6. 迁移不修改任何 SRS 和 Recovery 字段。
7. 标准词形匹配避免大小写和常见词形重复。

### 来源与归档

8. 导入词在统一页面可见。
9. 收藏已有导入词后显示双来源且只有一条主记录。
10. 取消双来源词的收藏后仍保留导入词和原排期。
11. 取消仅收藏词后自动归档。
12. 归档词不进入列表、ReviewQueue 或专项练习。
13. 归档不删除 reviewEvents 或日报事实。
14. 再次收藏或导入恢复同一 ID 和旧学习基础。
15. 同日重复导入不会因来源恢复而重复计外部复习。

### 页面与路由

16. 默认显示全部未归档词并按最近加入排序。
17. 收藏和导入筛选都包含双来源词。
18. 搜索覆盖英文、音标和中文释义。
19. 新词、学习中、待复习、长期巩固筛选保持。
20. A–Z 和待复习优先排序稳定。
21. 管理模式与选词模式互斥。
22. 导入完成后统一页面原地刷新。
23. `#/learn-words` 自动替换到 `#/vocab`。
24. 所有旧入口不再导航到独立学习词库页。
25. 手机和平板无横向溢出，App 菜单始终存在。

### 专项复习与回归

26. 今日新增同时包含收藏和导入新词，同词只计一次。
27. 最近七天使用本地日期窗口。
28. 手动选词直接使用统一主词 ID。
29. 专项评分不改变 SRS。
30. 正式闪卡、语境复习、文章生成、日报和 Agent 查询继续工作。

## 14. 交付边界

实现应在新的独立功能 worktree 中进行，基于 `feat/english-practice-machine` 当前已合并的日报版本。每个阶段测试先行并单独提交。完成后运行全量测试和手机/平板浏览器冒烟；只有用户另行要求时才构建 APK、合并或推送。
